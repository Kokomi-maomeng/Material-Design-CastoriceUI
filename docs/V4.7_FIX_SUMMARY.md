# v4.7 monitoring change map

| Item | Implementation and verification boundary |
|---|---|
| MON-01 | Restricted hot-load receiver, SAN/key/expiry checks, pair backup, TLS fingerprint and pinned HY2 forwarding verification, bounded retry and file rollback. Isolated binary integration and production delivery are separate gates. |
| MON-02 | Confirmed inactive/failed cores and verified absent listeners are offline; statistics and inventory uncertainty remain warnings with reason/generation/age. Unknown inventory has a 30-second notification budget; real failures do not wait. |
| MON-03 | Publish runtime timestamp before evaluating alerts; one-time 30-second initialization budget and independent watchdog. |
| MON-04 | Boot/PID/start-tick verification before and after probing, exclusive probe lock, atomic publication, start-event refresh and 10-second fallback. |
| MON-05 | Bounded protocol/network/resource/lifecycle history and immutable first/worst alert evidence. Schema additions preserve old rows and support backup-based rollback. |
| MON-06 | Core outage has one root alert with affected protocols; shared inventory warnings aggregate, independent mapping failures remain distinct. |
| MON-07 | Weighted 120s/24-packet quality window, two of three abnormal confirmation, two complete normal recovery. Partial samples cannot recover an event. |
| MON-08 | Optional explicit TCP and DNS service probes with independent times, results and bounded deadlines; no assumption every target accepts HTTPS. |
| MON-09 | HMAC-authenticated external probe reports, strict field validation, timestamp and persistent nonce checks; observer health is distinct from proxy failure. A dedicated server identity depends on safe support in the existing authentication mode; shared-password migration is a separate acceptance item. |
| MON-10 | Effective global/target thresholds are returned by the backend; cards and quality summary use target states, preserving a single-family anomaly. |
| MON-11 | Fixed monotonic per-domain scheduling, one worker per task, no overlapping catch-up; network and subscription stalls remain isolated. |
| MON-12 | Start lifecycle records independent of panel snapshots, independent collection watchdog, authenticated diagnostics and explicit health scope. |
| MON-13 | Timed-out ping retains observed replies and known counts, marks incomplete and excludes it from quality confirmation/recovery. |
| MON-14 | Rate-limited structured error categories, real observation times and duration fields; no exception messages or private URLs logged. |
| MON-15 | Time-stamped cgroup event deltas, PSI/memory/tasks/FD/CPU/TCP/interface evidence; bounded pressure burst. Limits remain unchanged without causal evidence. |
| MON-16 | Active/recovered-pending counts and filters; per-episode manual/bulk acknowledgement remains explicit. |
| MON-17 | Version metadata cached for 300s, certificate metadata for 60s, file signatures invalidate; fast liveness remains independent. |
| MON-18 | Actual timestamped per-target history, incomplete and missing gaps, current-round reply distribution labelled separately. |
| MON-19 | Same-batch target/family correlation, bounded official context and rate-limited route evidence; incident overlap is only a candidate association. |
| MON-20 | Conditional architecture reviewed: validated hot loading is preferred. No second instance/node is provisioned, and no TCP/QUIC migration promise is made. See monitoring runbook. |

Automated fault injection lives in `server/tests/test_v47_monitoring.py`; UI coverage supplements existing runtime/browser checks. Private deployment and connection-continuity evidence belongs outside this public repository. Public documentation must state only checks actually completed for the final release.

v4.7.1 corrects the MON-09 freshness boundary for observer clocks slightly ahead of the server. Server receipt time and bounded observation skew now prevent transient unavailable evidence while preserving expiry, failure confirmation and recovery requirements. See [patch release notes](https://github.com/Kokomi-maomeng/Material-Design-CastoriceUI/blob/v4.7.1/docs/RELEASE_NOTES_v4.7.1.md).
