# v5.2 alert-center changes

| Request | Result |
| --- | --- |
| Remove alert evidence displays | Removed the dialog, client fetch/types, evidence actions and source badge; retained protected local diagnostic records. |
| Keep useful logs | Shared SQLite incident/history/sample tables and structured backend journal; optional exact database, episode and sample locator. |
| Avoid files and noise for every fluctuation | Quiet observation windows, recurrence merging, minute coalescing for stable inventories, a bounded raw-sample budget and shared archives of at least 100 eligible incidents. |
| Make notifications understandable | Name affected service/observer/failing stage; collectors and unknown measurements are informational; known outages remain open until verified recovery. |
| Use severity levels meaningfully | Confirmed outage/expired certificate/exhausted quota: critical. Sustained significant quality or multiple-device business failure: warning. Single-device checks and legacy unverified measurements: info. Mild quality changes/monitoring gaps: info. |
| Combine filters and summary controls | Date range AND a single lifecycle state AND a single severity, within Pending or All records. Summary buttons control the same severity field. |
| Bound the Pending list | Both alert scopes and audits share 30 compact rows, 50 expanded rows and pagination. |
| Make list operations smooth | First-page cache makes compact/expanded toggles local. Keep existing rows during paging, animate size/page changes and honor reduced motion. |
| Remove redundant wording | Removed the acknowledgement/time-zone explanation and active/recovered counter paragraph. |
| Fix date and time readability | Normalize seconds/milliseconds, reject invalid epoch/uptime inputs and use larger, spaced local timestamps. |

Regression coverage includes local-day boundaries with explicit offsets, filter intersections, invalid ranges, exclusive severity choice, immediate cached toggles, observer grouping, observation deadlines, unknown recovery, raw-history preservation, acknowledgement recurrence, sample budgets and archive batching. Real-browser checks verify calendar interaction, scroll behavior and transitions. Production acceptance additionally checks deployed file digests, database preservation, authenticated routes and proxy-core continuity.

No claim is made that one external observer represents every user's connection. The log budget covers rotating raw samples; active/unacknowledged episodes and offline archives retain the documented capacity safeguards.
